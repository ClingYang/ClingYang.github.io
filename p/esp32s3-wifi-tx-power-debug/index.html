ESP32-S3 Wi-Fi 连不上：把发射功率降到 2 dBm 后发生了什么

记录一次 ESP32-S3 实板对照：默认功率上限下认证超时，限制到 2 dBm 后关联、获取 IP，并通过 Ping。

2026-11-23
阅读时长: 1 分钟

ESP32-S3 能扫到手机热点，发起连接后却卡在初始认证。关闭热点密码做对照，板子仍然报 reason=2。同一块板、同一根天线、同一个热点，把 Wi-Fi 最大发射功率限制在 2 dBm 后，串口出现了 STA_CONNECTED 和 STA_GOT_IP，随后 Ping 也通过了。

先看连接失败在哪一步

这次日志停在初始 802.11 认证，reason=2 对应 AUTH_EXPIRE。WPA2 四次握手发生在后面。既然临时开放热点也能复现，继续更换密码的价值就很低了。开放热点只用于短时对照。

除了核对驱动实际收到的配置，还试了关闭省电、固定信道带宽、重试，以及跳过屏幕、触控和音频初始化。默认发射功率上限下，认证超时仍然能复现。随后做了两个对照：

测试 默认上限档 2 dBm 上限档
板子作 STA，连接同一热点 初始认证超时 成功关联、获取 IP，Ping 通过
板子作 SoftAP，电脑扫描信道 11 对照时未扫描到信标 扫到信标，RSSI 约 −51 至 −54 dBm

电脑看到的 RSSI 是接收端读数。SoftAP 对照里，默认档未被扫描到这一结果也只能说明该轮测试的观察，不能据此计算板子的实际发射功率。

在 ESP-IDF 里怎样做功率对照

Wi-Fi 启动后、发起连接前设置功率上限。参数单位是 0.25 dBm，所以写入 8 对应 2 dBm。

ESP_ERROR_CHECK(esp_wifi_set_max_tx_power(8));

int8_t power_cap = 0;
ESP_ERROR_CHECK(esp_wifi_get_max_tx_power(&power_cap));
ESP_LOGI(TAG, "Wi-Fi TX power cap: %d quarter-dBm", (int)power_cap);

测试时先读取原始配置，分别记录默认档和低功率档的结果，结束后恢复原配置。尽量固定热点、信道、天线位置和 Wi-Fi 协议，每次只改变功率上限。判断连接可用时至少等到 IP_EVENT_STA_GOT_IP，再检查实际网络连通性。 ESP-IDF 发射功率 API

临时方案和后续排查

这块样板暂时用 2 dBm 上限配合 802.11b/g。首次启动由用户从扫描列表选网，获得 IP 后才保存这组连接配置。已验证设备复位后能用保存的配置重新入网。

根因还待测。下一轮优先比较发射瞬间的供电波形，再用已知正常的天线和另一块板做交叉验证。距离稍远或者换了天线时，也要重新测低功率档的连接余量。
